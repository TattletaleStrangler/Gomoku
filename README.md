# Гомоку (5 в ряд) — Android-приложение на Kotlin

Нативное Android-приложение для игры в гомоку против компьютера в офлайн-режиме.
В качестве сильного AI используется движок **Rapfi** (по протоколу
Gomocup/Piskvork); при его недоступности — или на досках 13×13 / 19×19 —
автоматически используется встроенный AI (альфа-бета + эвристика).

Реализовано по техническому заданию `TZ_GOMOKU.md`.

## 2. Сборка

1. Установите **JDK 17** и **Android Studio** (или Android SDK).
2. Откройте каталог `Gomoku/` в Android Studio и нажмите Sync / Build.
   - Если Gradle не находит SDK: укажите его в `local.properties`
     (`sdk.dir=...`) или задайте переменную окружения `ANDROID_HOME`.
   - Проект использует Gradle 8.2 + AGP 8.2.2. Файла `gradlew` в репозитории
     нет (это бинарный wrapper); Android Studio сама загрузит Gradle. Чтобы
     получить обёртку: `gradle wrapper --gradle-version 8.2`.
3. Соберите debug APK:
   ```
   ./gradlew assembleDebug        # результат: app/build/outputs/apk/debug/app-debug.apk
   ```
4. Установите на arm64-устройство и запустите.

## 3. Интеграция движка Rapfi (самопроверка)

Android 10+ (API 29) запрещает `exec()` файлов из `filesDir` (W^X policy).
Поэтому движок размещён в двух местах (подробнее — `assets/engine/README.md`):

- **Бинарник:** `jniLibs/arm64-v8a/librapfi.so`. Упаковывается как нативная
  библиотека, ОС распаковывает его в `nativeLibraryDir` — единственное место,
  где `exec()` разрешён. Никакой `chmod` не нужен.
- **Данные (config + NNUE-веса):** `assets/engine/`. `NativeExe` рекурсивно
  копирует их в `filesDir/engine/`, и этот каталог становится рабочим для
  процесса — Rapfi находит конфиг и веса рядом.

Самопроверка (ТЗ §4.1):
  1. `START 15` → ожидается `OK` (читает все строки до `OK`);
  2. `BEGIN` → ожидается один ход с корректной координатой.
  3. Причина ошибки видна в шапке: «Движок: встроенный (причина)».

При любой ошибке — откат на встроенный AI. На досках ≠ 15×15 Rapfi не
используется, задействуется встроенный AI.

### Протокол Gomocup/Piskvork (ТЗ §4.2)

| Направление | Команда | Описание |
|---|---|---|
| приложение → движок | `START 15` | инициализация |
| движок → приложение | `OK` | подтверждение |
| приложение → движок | `INFO rule 0/5` | правила: свободные (0) или рендзю (5) |
| приложение → движок | `BEGIN` | первый ход движка (пустая доска, движок играет чёрными) |
| приложение → движок | `BOARD` + строки `x,y,field` + `DONE` | полное состояние доски |
| движок → приложение | `x,y` | ход движка |
| приложение → движок | `END` | завершение партии |

`field` = **1** для «своего» камня (цвет AI), **2** для камня соперника — так
движок корректно играет и чёрными, и белыми.

### Таймауты и перезапуск (ТЗ §4.3)

Чтение ответа движка выполняется с таймаутом (12 с) через отдельный поток,
перекладывающий строки в `LinkedBlockingQueue`. При таймауте/некорректном ходе:
процесс уничтожается (`END` → `destroy` → `destroyForcibly`), движок
перезапускается, текущая доска воспроизводится через `BOARD … DONE`, и ход
запрашивается повторно. В `onCleared` ViewModel процесс завершается принудительно.

## 4. Соглашение о координатах (ТЗ §4.4)

- Координаты **нумеруются с нуля**: `(0,0)` — левый верхний угол, `(7,7)` —
  центр доски 15×15, диапазон `0..14`.
- При разборе ответа движка берётся **последняя** строка с допустимой
  координатой: Rapfi может выводить служебные строки (`DEBUG`, `MESSAGE` …)
  перед ходом. Это исправляет баг «смещения ходов» из эталонной реализации
  `peilian-qipan`.
- Перед сдачей проекта рекомендуется прогнать фиксированные позиции (см. §7).

## 5. Встроенный AI (резервный)

`BuiltInAI` — один класс без внешних зависимостей:

- **негамакс с альфа-бета отсечением**;
- **эвристическая оценка** по шаблонам (открытая/закрытая четвёрка,
  открытая/закрытая тройка и т.д.);
- глубина **4** («обычный») / **6** («сильный»), мягкий лимит времени ~1,8 с;
- ограниченный набор ходов-кандидатов (радиус 2 от камней) + сортировка по
  эвристике + итеративное углубление — отклик на 13×13 / 19×19 < 2 с;
- при включённых запрещённых ходах чёрные запрещённые ходы отсекаются из поиска.

---

## 6. Правила и запрещённые ходы (рендзю)

- Победа: **пять камней в ряд** по горизонтали/вертикали/диагонали.
- При включённой опции «Запрещённые ходы чёрных» для чёрных действуют правила
  рендзю: **overline** (6+ в ряд), **четыре-четыре**, **три-три** — поражение.
  Проверка выполняется и для хода человека, и для хода AI (свой ход чёрных
  движок/встроенный AI не сыграет запрещённо).
- Отмена хода (`undo`) снимает один полный раунд: ход AI + ход игрока
  (критерий приёмки № 7), вплоть до пустой доски.

---

## 7. Сохранение состояния (критерий № 6)

- Позиция сериализуется в `SharedPreferences` после каждого хода
  (`GomokuGame.encode()/decode()`: размер, цвет игрока, флаг запретов, победитель,
  флаг окончания, история ходов). История хранится, чтобы работали отмена и
  нумерация; правила при восстановлении заново не пересчитываются.
- Настройки (доска, цвет, уровень, тема, номера ходов, запреты) — отдельные
  ключи `SharedPreferences`.
- Поворот экрана заблокирован (`screenOrientation=portrait`), поэтому Activity
  не пересоздаётся; состояние также переживает сворачивание/убийство процесса.

выбор также доступен в настройках.

## 9. Известные допущения / что проверить на устройстве

- Бинарник Rapfi в репозиторий **не включён** (собирается отдельно,
  `tools/build_rapfi.sh`). Без него приложение полностью работает на встроенном AI.
- Протокол и соглашение о координатах реализованы по документации Gomocup;
  рекомендуется прогнать фиксированные позиции на реальном бинарнике (ТЗ §4.4).
- Диалог настроек использует базовую Material-тему (не перекрашивается под
  кастомную тему) — это не влияет на главный экран.
