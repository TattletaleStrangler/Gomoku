# Как проверить онлайн-игру локально

Инструкция для проверки партии «на двоих»: сервер поднимается в Docker на этом
компьютере, клиент — debug-сборка приложения на эмуляторе или телефоне.

## Что нужно

- Docker Desktop (или Docker Engine с плагином compose).
- JDK 17 — им собирается клиент.
- Android SDK и эмулятор (или два устройства).
- Свободные порты: **8080** — сервер, **5432** — PostgreSQL (только localhost).

## 1. Поднять сервер

```powershell
cd Backend
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# откройте .env и задайте POSTGRES_PASSWORD (24–32 символа A-Za-z0-9)
# и JWT_SECRET (48 байт, например: openssl rand -base64 48)
docker compose up --build
```

Проверка, что сервер жив:

```powershell
curl.exe http://localhost:8080/actuator/health
# {"status":"UP"}
```

Полезное:

- логи приложения — `docker compose logs -f app`;
- остановить, сохранив аккаунты и партии — `docker compose down`;
- стереть всё, включая базу, — `docker compose down -v`;
- порт сервера меняется в `.env` (`SERVER_PORT`), тогда и клиент нужно собрать
  с новым адресом (см. ниже).

Сервер публикует порт 8080 наружу, база — только на `127.0.0.1:5432`.

## 2. Собрать и установить клиент

Адрес сервера вшивается в сборку через `BuildConfig.API_BASE_URL`, поэтому для
разных устройств может понадобиться разная сборка.

**Вариант 1 — два эмулятора (проще всего).** Debug-сборка по умолчанию ходит на
`http://10.0.2.2:8080` — это хост-машина с точки зрения эмулятора:

```powershell
cd Gomoku
.\gradlew.bat installDebug
```

`installDebug` ставит APK на все подключённые устройства (`adb devices`), так что
второй AVD достаточно запустить и повторить команду. Оба эмулятора видят
`10.0.2.2` — отдельная настройка не нужна.

**Вариант 2 — эмулятор + телефон, общий адрес.** Соберите APK с адресом
компьютера в локальной сети и поставьте его на оба устройства:

```powershell
ipconfig                     # найдите IPv4, например 192.168.1.42
.\gradlew.bat assembleDebug -Pgomoku.apiBaseUrl=http://192.168.1.42:8080
adb -s emulator-5554 install -r app\build\outputs\apk\debug\app-debug.apk
adb -s <серийный-номер-телефона> install -r app\build\outputs\apk\debug\app-debug.apk
```

Порт 8080 должен быть разрешён в брандмауэре Windows, телефон — в той же сети.
Если эмулятор не достаёт до LAN-адреса, соберите два APK: вариант 1 для
эмулятора и вариант 3 для телефона.

**Вариант 3 — телефон по USB.** `adb reverse` пробрасывает порт телефона на
компьютер, но только для этого телефона; эмулятору нужен свой APK:

```powershell
adb reverse tcp:8080 tcp:8080
.\gradlew.bat assembleDebug -Pgomoku.apiBaseUrl=http://127.0.0.1:8080
adb -s <серийный-номер-телефона> install -r app\build\outputs\apk\debug\app-debug.apk
```

Не ставьте эту сборку на эмулятор: `127.0.0.1` внутри эмулятора — это он сам.

**Вариант 4 — два телефона по Wi-Fi.** Как вариант 2: адрес компьютера в
`-Pgomoku.apiBaseUrl`, APK — на оба телефона.

Release-сборка ходит на `https://api.gomoku.invalid` — для локальной проверки
используйте debug.

## 3. Сыграть партию

1. **Первый игрок.** На первом устройстве откройте «Онлайн» (иконка в шапке
   главного экрана) → «Регистрация» → никнейм и пароль (от 8 символов).
2. **Создать комнату.** Правило (свободное или рэндзю), контроль времени
   (без часов, классика, рапид, блиц) и цвет: чёрные (по умолчанию), белые или
   «любой» — тогда цвет выберет вошедший → «Создать». Появится код из шести
   символов и надпись «Ждём соперника».
3. **Второй игрок.** На втором устройстве — «Онлайн» → зарегистрируйте второй
   аккаунт → «Войти по коду» → введите код. Можно пожелать цвет: он учитывается,
   только если создатель оставил «любой»; иначе комнату определяет выбор
   создателя. Партия начнётся сразу у обоих.
4. **Быстрая игра (альтернатива коду).** Оба игрока выставляют одинаковые правило и
   контроль времени и нажимают «Найти соперника»: первый попадает в ожидание
   публичной комнаты, второй тем же нажатием сразу открывает партию. Кнопка
   «Обновить» в разделе «Открытые игры» показывает публичные комнаты (никнейм,
   рейтинг, правило, контроль, цвет); нажатие на строку заходит по коду. Быстрая
   игра — рейтинговая: после партии в строке результата видна дельта, а в профиле —
   новое значение рейтинга; партия по коду рейтинг не меняет.
5. **Ходы.** Доска, часы и статус («Ваш ход» / «Ход соперника») обновляются по
   WebSocket. Ход, сделанный на одном устройстве, появляется на другом за доли
   секунды.
6. **Отмена хода.** Сделайте ход и в течение **2 секунд** нажмите «Отмена (N)».
   Соперник увидит панель «Соперник просит отменить ход» и должен ответить за
   **3 секунды**. Согласие убирает камень; запросивший видит на его месте
   светло-голубой призрак до своего следующего хода. Попыток — по три на игрока.
7. **Сдача.** Кнопка «Сдаться» завершает партию сразу у обоих.
8. **Переподключение.** Сверните приложение на одном устройстве, сделайте ход на
   другом и вернитесь — клиент догонит состояние по снимку с сервера.
9. **История и повтор.** После одной-двух завершённых партий нажмите «История
   партий»: список идёт новыми первыми, в строке — соперник с рейтингом, результат,
   правило, контроль, дельта рейтинга и число ходов. Нажатие на строку открывает
   повтор: ползунок листает ходы, подпись показывает «Ход N: H8 (чёрные)», внизу —
   итог партии.
10. **Таблица лидеров.** Кнопка «Таблица лидеров» показывает игроков с завершёнными
   партиями по рейтингу: место, ник, рейтинг и запись побед/поражений/ничьих. Своя
   строка выделена цветом; аккаунт без завершённых партий в списке не виден.
11. **Реванш.** На экране завершённой партии нажмите «Сыграть ещё»: у вас появится
   ожидание, у соперника та же кнопка будет называться «Принять реванш». После его
   нажатия партия начнётся у обоих, причём цвета поменяются местами.
12. **Блок и жалоба.** На экране завершённой партии нажмите «Больше не играть»: появится
   вопрос «Заблокировать соперника?» с ником и подсказкой, где разблокировать. После
   подтверждения тот же соперник пропадёт из «Открытых игр» и больше не подберётся.
   На экране повтора (история → строка партии) есть «Пожаловаться» с коротким списком
   причин.
13. **Чёрный список.** «Онлайн» → «Заблокированные»: видно ник и дату блокировки, у каждой
   строки кнопка «Разблокировать». После нажатия игрок снова попадается в лобби и в
   быстром подборе, а строка исчезает из списка. Проверьте, что у второго аккаунта
   чужой список пуст.
14. **Ничья.** В идущей партии нажмите «Ничья»: соперник увидит панель «Соперник
   предлагает ничью» с обратным отсчётом (10 секунд), его часы на это время стоят.
   «Да» завершает партию ничьей у обоих, «Нет» возвращает часы и продолжает игру.

## 4. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| «Нет соединения» | сервер запущен? `curl http://localhost:8080/actuator/health`; на эмуляторе адрес — `10.0.2.2`, а не `localhost` |
| 401, «сессия истекла» | `adb shell pm clear com.oldmermaidman.gomoku` и войти заново |
| Сокет молчит | `adb logcat -s GameSocket` и `adb logcat -s ApiClient`; сервер отвечает `PONG` на `PING` |
| Сервер не стартует | `docker compose logs app`; чаще всего не заданы `POSTGRES_PASSWORD` и `JWT_SECRET` в `.env` |
| Порт 8080 занят | поменяйте `SERVER_PORT` в `.env`, пересоберите клиент с новым адресом |
| Два эмулятора тяжелы | один эмулятор + один телефон; два аккаунта на одном устройстве одновременно не уживаются (сессия одна) |

## 5. Проверка без второго устройства

Второго игрока можно изобразить curl'ом — так проверяют сервер, не поднимая
второй телефон. Пример для PowerShell (замените код комнаты):

```powershell
$base = "http://localhost:8080/api/v1"

# второй аккаунт
$bob = Invoke-RestMethod "$base/auth/register" -Method Post -ContentType "application/json" `
  -Body '{"nickname":"bob","password":"password-123"}'

# вход в комнату по коду, который показал телефон
$game = Invoke-RestMethod "$base/games/join" -Method Post -ContentType "application/json" `
  -Headers @{ Authorization = "Bearer $($bob.accessToken)" } -Body '{"code":"ABC123"}'

# ход за белых (ply — номер хода из снимка)
Invoke-RestMethod "$base/games/$($game.gameId)/moves" -Method Post -ContentType "application/json" `
  -Headers @{ Authorization = "Bearer $($bob.accessToken)" } -Body '{"ply":2,"x":7,"y":8}'
```

Дальше ходы можно делать в обе стороны: приложение — за чёрных, curl — за белых.
